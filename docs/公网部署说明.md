# 公网体验版部署说明

此版本把网页、FAQ、资料检索和模型调用运行在服务器上。访问者只需要浏览器；你的个人电脑可以关机。GitHub 只保存代码，不能代替这个持续运行的服务。当前准备了 Docker Compose 部署文件，尚未购买服务器、创建域名或执行云上部署。

## 部署结构

浏览器 → HTTPS / Caddy → FastAPI 单进程 → FAQ / RAG 资料 → 火山模型 API。

- 体验页公开访问；知识库和资料维护仅管理员登录后开放。
- 管理员入口为 `https://你的域名/admin`，浏览器弹出账号密码框。需要在 HTTPS 下使用。
- 不开放跨站 CORS，也不开放 `/docs`、`/redoc`、`/openapi.json`。
- 访客会话由签名、HttpOnly、Secure 的浏览器 Cookie 绑定。其他浏览器即使知道会话 ID，也不能使用它。
- 当前是浏览器体验版；第三方系统直接调用、API Token、多租户和计费并未实现。

## 需要准备

1. 一台能持续运行 Docker Engine 与 Docker Compose 的 Linux 云服务器。模型需要从服务器访问火山 API。包含本地向量模型时，建议从 2 核、4 GB 内存测试；这是起点建议，不是性能保证，实际并发要压测。
2. 一个解析到服务器公网 IP 的域名。中国内地服务器的域名和备案要求需要按服务商要求办理。
3. 开放服务器入站 80、443 端口；管理 SSH 端口按自己的来源 IP 限制。应用 8000 端口不发布到公网。
4. 火山 API Key、独立管理员密码、独立 Cookie 签名密钥。所有实际凭据只填写在服务器的 `.env.deploy`，不要提交到 GitHub、截图或发给体验者。

## 首次启动

在服务器项目根目录操作：

```sh
cp .env.deploy.example .env.deploy
```

编辑 `.env.deploy`，至少填写：

- `PUBLIC_DOMAIN`：真实域名，不带 `https://` 或路径。
- `ADMIN_USERNAME`：管理员用户名。
- `ADMIN_PASSWORD`：至少 16 字符的随机密码。
- `SESSION_SECRET`：至少 32 字符、与密码不同的随机值。
- `ARK_API_KEY`：火山平台 API Key；为空时进入演示 mock 模式，不会产生真实大模型回答。

可分别用 `openssl rand -hex 24` 和 `openssl rand -hex 32` 生成密码与签名密钥，再填入配置文件。不要把示例里的 replace 占位值留着，公网启动会拒绝它。

```sh
docker compose --env-file .env.deploy up -d --build
docker compose --env-file .env.deploy ps
```

首次构建会安装 Python 依赖，并下载固定版本、校验哈希的 ONNX 句向量模型；不执行模型仓库的远程代码。依赖下载、模型下载、HTTPS 证书申请都需要网络，构建失败要先解决网络问题。本版已在本机成功构建 Linux 镜像，并验证容器启动、模型就绪、后台鉴权及会话隔离；域名解析、Caddy 实际证书签发和云服务器访问仍需上线时验收。

确实无法下载模型时，可暂设 `DOWNLOAD_SEMANTIC_MODEL=false` 重新构建，但此时应明确看到向量模型缺失状态；不能声称语义检索已经可用。后续能下载后恢复为 true，重新构建。

浏览器打开 `https://你的域名/`。首次 Caddy 申请证书可能需要一些时间，前提是域名解析正确且 80、443 可访问。正常后再分享链接。

## 上线前验收

- 关闭你自己的本地服务，手机使用移动网络打开公网网址，确认四款商品和 FAQ 回复可用。
- 在资料库放入已确认的产品材料，测试一条需要结合多段材料的问题，确认 RAG 建议带实际来源；无资料时不能编答案。
- 未登录访问 `/knowledge`、`/materials`、`/api/faq`、`/api/scenes`、`/api/materials` 应要求管理员登录。
- 用两个不同浏览器创建会话，确认彼此隔离。不要输入真实客户隐私用于公开演示。
- 检查管理密码、签名密钥和 API Key 不出现在源码、网页或日志中。
- `/api/health` 可查看模型配置和向量加载状态；模型配置成功不等于实际调用成功。还需运行一条 RAG 问题，看到“基于资料生成”及有效引用，才能确认真实接口可用。配错密钥或调用失败时应显示摘录与原因。

## 限额与当前边界

默认每个来源 IP 每分钟最多 60 次 API 操作，其中提问和 RAG 辅助共 20 次；每分钟最多新建 10 个会话。所有访客共享每天 500 次“聊天 + RAG 辅助”请求和 3 个并发请求额度。RAG 按钮也算一次请求。

每个浏览器最多 10 个会话，服务器总会话最多 200 个。空闲超过 1 小时、且没有正在处理请求的会话会清理。服务重启后访客需新建会话。

这些配额是单进程内存控制，按 UTC 日期重置，重启也会清空计数；它们不能替代火山平台的实际用量告警和费用限制。每次请求可能产生多次模型调用，次数不是 token 数或人民币额度。公开分享前应同时配置模型平台可用的额度/告警。后续若有更多用户，需把会话、限流、预算迁移到 Redis/数据库，不能直接增加 Uvicorn workers。

反向代理只在 Compose 内网访问应用，应用才信任代理头；不要把带 `--forwarded-allow-ips '*'` 的应用端口单独暴露公网。多个访客共用同一公网出口时会共用 IP 限额，体验阶段可按实际情况调整。

## 知识与日志持久化

`knowledge_data` 保存整个 `/app/data`，包含 FAQ、产品参数、来源材料和 `rag_documents.json`；`service_logs` 保存运行日志；Caddy 证书存到独立卷。新建空卷时复制镜像内已确认知识作为初始数据，后续更新镜像不会覆盖服务器上维护的知识。

更新代码后可执行：

```sh
docker compose --env-file .env.deploy up -d --build
```

更新前先备份。示例把数据和日志复制到当前服务器本地的备份目录：

```sh
mkdir -p backups
docker compose --env-file .env.deploy cp app:/app/data ./backups/data
docker compose --env-file .env.deploy cp app:/app/logs ./backups/logs
```

备份目录也包含内部资料或用户输入，不要上传公开仓库。示例重复运行前应另取带日期的新目录名，避免误覆盖。生产环境应增加服务器外的定期备份和保留策略。

停止服务用 `docker compose --env-file .env.deploy stop`。不要随意执行 `down -v`，它会删除持久化卷。服务器上维护的知识与电脑本地知识是两份数据，不会自动同步。

## 本地开发

默认 `APP_MODE=local`，保留原来的桌面启动器、`http://127.0.0.1:8002/` 和本地维护流程。公网模式会因为缺少管理员凭据、密钥或明确域名而拒绝启动，避免无意开放后台。

## 已完成的本机验证

本版通过 367 项自动化测试，包含 FAQ、RAG、资料维护、前端交互与公网访问边界。另完成 Linux 镜像构建与临时容器检查：

```sh
docker build --tag presales-ai:demo-check .
python scripts/check_deployment.py
```

检查脚本仅临时绑定本机随机端口，使用独立随机测试凭据与 Mock 模式，不使用真实模型密钥；验证只读根目录、非 root 用户、数据卷、向量模型、FAQ、资料检索及访客隔离后清理临时容器和测试卷。它不会开启公网，也不会修改运行中的知识库。

本地工作台还已用现有火山 Seed 2.0 Lite 完成一次真实的跨款尺寸建议生成，引用了两款各自的确认资料。该结果说明调用链可用，不代表所有问法、事实正确率和公网并发已通过验收。
