# FAQ 与 RAG 的分工和体验方式

本版在保留 FAQ 自动回复的基础上，新增独立的资料辅助流程。资料辅助服务测试者和人工客服，不会自动向顾客发送生成结果。

## 在网页上怎么体验

1. 打开咨询测试，选择商品与接待状态，发送客户原话。客户问题下面仍显示识别出的意图。
2. FAQ 命中时直接返回已维护的答案；复杂问题可以在右侧点“查资料”。未找到答案时，测试助手会自动尝试查资料。
3. 右侧“资料辅助 · RAG”显示简短建议、意图建议和引用来源。展开来源可看到实际检索出的文字、商品和出处。
4. “基于资料生成”代表真实模型调用成功且通过基础引用检查；“资料摘录”代表当前只提供原资料，不能当成模型生成已经成功。未找到资料时只提示补充信息。
5. 有完整依据的生成建议可以进入“待核实 FAQ”草稿。维护者确认意图、商品及接待条件后保存，答案仍为待核实，需再次审核启用。

可先试：

| 客户问题 | 重点观察 |
| --- | --- |
| 全伸缩款 110 高的高度和长宽各能调多少？ | 是否找到不同属性的资料段，数字归属是否正确 |
| 全伸缩款和免安装款的长宽调节范围分别是多少？ | 是否分别引用两款资料，而不是把两款参数混在一起 |
| 小狗款的绝对长度和宽度是多少？ | 当前仅确认长宽调节量 ±4 厘米，应核实基准尺寸，不得自行推导 |
| 双十一还能再便宜多少？ | 没有本次活动依据时不能编折扣或价格承诺 |

生成建议仍可能出错；引用、数字和范围检查不能证明所有事实都正确。当前继续采用人工审核，不把相似度当正确率。

## 资料从哪里来

导航中的“资料库”用于维护文字材料。首批九份材料来自商家在聊天中确认的四款高度、长宽调节范围及共同套装结构。材料可以绑定商品、客服接待类型、业务状态、有效时间和确认日期。

首版支持粘贴文字，不包含 PDF 自动解析、图片 OCR 或网页抓取。图片中的参数须先核实，再整理成文字。新资料默认“待核实”，审核后切换为“已启用”才会参加检索；保存时有版本冲突检查、自动备份和原子写入。

独立资料与 FAQ 都属于本项目知识库，但目前是两份维护源。**修改 FAQ 不会自动修改资料，修改资料也不会自动修改 FAQ。** 修改商品参数时应同时核对这两个入口，避免内容冲突。后续可以把尺寸等基础事实统一维护，再由同一来源生成 FAQ 和资料索引。

RAG 也可参考符合商品及接待条件、已启用且有来源的 FAQ。此前发生冲突的尺寸与套装结构旧条目不作为 RAG 的补充依据，优先使用独立确认资料；待核实、停用或不符合条件的条目不会参与。

## 实际流程

问题 → 识别商品及接待范围 → 检索资料片段 → 将问题和片段交给模型 → 检查引用及基础参数 → 仅在测试助手显示建议。

向量模型可用时使用关键词与向量的混合检索；缺失或失败时明确降级到关键词。真实生成沿用现有火山接口设置，不需要再填写一套大模型密钥。无依据时不调用生成，网络超时或输出不合格时显示摘录与状态。

意图建议目前来自轻量主题规则，用于帮助维护者判断知识归属，并非新训练的分类模型。它不会取代 FAQ 原有的意图识别，也不会直接创建新意图。FAQ 草稿里的 RAG 来源清单先保留在当前浏览器短期上下文，当前版本不会擅自把模型结果登记为已审核的持久来源。

## 公网体验与管理

默认仍是本地运行。公网部署时，访客可以聊天和查看资料建议，不能进入知识维护或沉淀草稿；管理员登录后可维护。

GitHub 上的代码、当前电脑上的知识和云服务器上的知识不会自动同步。云端运行后，你的电脑可以关机，但云服务器必须保持运行。具体部署和验收见 [公网部署说明](公网部署说明.md)。

RAG 的基本方法参考 [Microsoft 的检索增强生成说明](https://learn.microsoft.com/en-ie/azure/ai-foundry/concepts/retrieval-augmented-generation?view=foundry-classic)；本项目实现不依赖 Azure 服务。
