## 1. 在 VS Code 中运行

用 VS Code 的“文件 → 打开文件夹”打开本 README 所在的 `presales-ai` 文件夹。推荐 Python 3.11 及以上，本次验证环境为 Windows + Python 3.14.7。

在 VS Code 的 PowerShell 终端执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

不需要激活虚拟环境，也无需修改 PowerShell 执行策略。已有 `.env` 时不要重复复制覆盖。浏览器打开 http://127.0.0.1:8000 ，接口文档打开 http://127.0.0.1:8000/docs 。按 Ctrl+C 停止服务。端口已占用时，停止先前实例或改为 `--port 8001`。

也可在 VS Code 安装官方 Python 和 Python Debugger 扩展，选择 `.venv` 解释器后按 F5，运行附带的“售前客服 V0.1”配置。开发时可在命令末尾加 `--reload`，每次后端重启会清空内存会话，页面需新建会话。

本项目仅绑定回环地址用于本机测试。没有登录、权限或多进程共享状态，不应直接部署为公网客服服务；只运行一个 worker。

## 3. 项目结构与处理流程

```text
presales-ai/
  app/
    main.py          FastAPI 路由、请求校验和商品事件
    config.py        环境变量与路径
    service.py       会话状态、商品确认、流程控制、日志和兜底
    knowledge.py     商品范围过滤、字段检索、分句覆盖检查
    model.py         Mock / OpenAI 兼容 HTTP 模型适配器
  data/knowledge.json  三款商品事实、真实卖点和店铺规则
  static/            聊天页面、样式、交互
  tests/test_system.py 自动化测试
  docs/TEST_REPORT.md  测试记录与范围
  logs/events.jsonl   首次运行时生成，不纳入版本管理
  .vscode/launch.json VS Code 调试入口
  .env.example       环境变量示例，不含密钥
  .gitignore
  requirements.txt
```

流程：消息 → 人工接管状态检查 → 商品识别/冲突追问 → 人工事项拦截 → 按商品 ID 和店铺范围检索 → 覆盖检查 → 模型证据选择 → ID 校验 → 用可信原文组织回复 → 记录调试信息。

商品识别采用客户选择/明确提及优先，其次使用已确认商品；选择与文字冲突、多商品同时提及会先追问。客服卡片绝不自动确认。针对不明指代会保存一个待确认问题，用户随后直接回复商品名称或 ID 时可继续回答。历史最多保留 20 条消息；历史用于调试，V0.1 不把整段历史发送给模型。

状态分为 `answered` 正常回答、`clarify` 追问、`handoff` 人工接管、`error` 系统故障。后两者都会设置 `needs_human=true`。不会静默丢弃有效咨询；非法请求有 4xx 错误，网页也会明确显示。网络失败时页面会显示故障，但浏览器尚未送达服务端的消息无法保证写入后端日志。

## 4. 为什么模型没有自由改写商品事实

V0.1 使用保守的“证据选择 + 确定性话术”模式。API 会真实调用模型，让它选择 `answer/handoff` 和证据 ID；只接受当前检索返回的完整证据列表，最终事实文本由本地知识条目渲染。模型夹带的自由文本不会发送给客户。

这是准确性优先的实现取舍：能防止模型在已选事实之外添加参数或承诺，但不等于能消除检索、知识录入和商品指代中的所有错误。当前回答自然度有限，冷门说法会较多转人工；尚未实现自由生成再做语义级事实核验。Mock 模式按同样接口返回本地证据 ID，不模拟真正的语义理解。

字段检索不是向量检索，没有相似度分数，也没有“答案正确率”评分。分句中包含不认识的内容、缺失属性或无命中时，不发送部分答案，直接交人工。

## 5. 切换至真实国内轻量模型

编辑本地 `.env`：

```dotenv
MODEL_MODE=api
MODEL_API_KEY=在你本地填写真实密钥
MODEL_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
MODEL_NAME=qwen-flash
MODEL_TIMEOUT_SECONDS=12
```

重启服务并新建会话。页面右上角应显示“模型 API 模式”，成功回答的调试结果会显示 `api_success`。模型名称、密钥和接口地址都必须与百炼控制台当前开通的地域/业务空间一致；示例名称无权限或停用时更换为账户可调用的轻量模型。

- `auto`：有密钥调用 API，无密钥使用 Mock。
- `mock`：始终在本地运行，不发送网络请求。
- `api`：强制 API；缺密钥会显示系统故障并转人工，不会伪装成调用成功。
- 适配器请求 `${MODEL_BASE_URL}/chat/completions`，传递 Bearer 密钥、模型名、系统约束和当前问题/证据。
- API 模式会将当前问题和命中资料发送给所配置的模型服务；用真实资料之前请确认公司授权。
- 非 JSON、无有效证据、拒答或超时都有明确状态；不自动重试，避免增加等待和费用。

密钥不写在代码、日志或浏览器中；`.env` 已被忽略。当前密钥及形如 `sk-...` 的内容会从调试日志中脱敏，但这不替代生产环境的完整隐私治理。

已参考阿里云官方说明：
- [OpenAI 兼容 Chat 接口](https://www.alibabacloud.com/help/en/model-studio/qwen-api-via-openai-chat-completions)
- [百炼及 Qwen-Flash 低延迟模型介绍](https://www.alibabacloud.com/help/en/model-studio/what-is-model-studio)
- [北京地域 DashScope 地址示例](https://www.alibabacloud.com/help/zh/model-studio/model-calling-in-sub-workspace)

本次没有真实 API Key，因此没有验证真实模型的可用性、效果、价格、延迟或额度。

## 6. 查看检索与错误日志

页面的“回答依据”中查看：原始问题（密钥脱敏）、商品识别依据、当前商品、候选卡片、命中事实及来源、缺失字段、未覆盖分句、模型状态、错误类型、请求 ID 和耗时。

`product.P001.material` 表示 P001 的材质事实；`store.shipping` 表示店铺发货规则。`kind` 区分商品事实、已核实卖点和店铺规则。

终端实时查看日志：

```powershell
Get-Content .\logs\events.jsonl -Encoding UTF8 -Tail 10 -Wait
```

每行一个 JSON 事件，日志达到约 2 MB 后轮转，保留 3 个备份。异常只记异常类型，不记录可能包含密钥的异常正文。`ReadTimeout` 表示模型请求超时，`HTTPStatusError` 表示 HTTP 调用失败，`JSONDecodeError` 表示输出不符合 JSON 协议；可用请求 ID 对应页面与日志。运行期 4xx 请求校验错误由接口/页面显示，不作为正常咨询写入 events.jsonl。

修改知识 JSON 后重启服务。商品事实只应来自核实资料，卖点必须可由事实支持，不能把广告承诺填入事实字段。

## 9. 升级至混合 RAG 的顺序

1. 整理真实商品资料，保留 `product_id / field / source / updated_at / kind`，给每条事实稳定 ID；单独标注政策适用范围和例外。
2. 用脱敏的真实问法制作标注集：正确商品、应命中事实、应回答/追问/转人工，按商品和问法划分训练/验证集。
3. 在 `Knowledge.retrieve()` 后新增可替换检索器，先硬过滤已确认商品 ID；店铺规则独立检索，不能跨商品补齐属性。
4. 加入中文关键词/BM25 检索与中文向量检索，用 RRF 等方式融合候选；随后再加重排序和 Top K，保留完整证据链。
5. 用标注集调阈值，分别测商品识别准确率、召回率、无依据回答率、合理拒答率、人工率和延迟；相似度仅用于相关性，不当作答案正确率。
6. 检索稳定后才增加自然话术生成、逐项事实核验、对话摘要和人工协作；每次改动重跑回归测试，再决定是否进入下一版。

优先把“检索器”升级好，保留现有商品确认、证据约束、状态机和兜底机制。
